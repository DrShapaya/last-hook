## L1 — контракт уровня

- `scripts/level_catalog.gd` (`LevelCatalog`): `LEVELS` (LevelDefinition: id, location_slot, display_name, height_units, acts, unlock_rule), `ACTS` (ActDefinition: share→y_start/y_end, biome_profile, intro_rule, route_patterns, allowed_grips, hazards, landmarks, safe/risky_route_rules, objectives, silhouette, width, props, variants, reward_tag, contract_tag), `HAZARDS` (HazardDefinition: telegraph_time, active_time, calm_time, collision, damage, affected_edges, safe_exit_tags, kind, force, telegraph).
- Старые id сохранены; новые названия — в `display_name` и `balance.json["locations"][i]["name"]`.
- `MountainWorld.GENERATION_VERSION = 14`, `generation_version_for()` = 14 для всех слотов. Legacy выбирается **только** для сохранённой попытки v4 на слотах 1/2, Massif v6–v13 — только для сохранённых попыток слота 0 (`MountainWorld.resumable`). Скрытого переключения на legacy больше нет (`main.gd` rope path теперь по `layout is LegacyMountainLayout`, а не `location==0`).
- Акт виден: `world.act_at(y)`, `world.debug_state()`, `main.debug_state()`, HUD (название акта вместо зоны), тост «Акт N · …» с правилом и лог `ACT_ENTER`.
- Актовый seed stream: `ExpeditionLayout.act_rng(act, local, stream)` по ключу id акта; старт акта — точка из его потока; последние ряды акта ведут к старту следующего. Жизнь вспомогательных опор берётся из позиции, а не из id. Проверено: вариант одного акта не сдвигает ни одной опоры, полки или опасности соседних.
- Профиль, цвет и погода скалы по акту: `layout.profile_id_at`, `MassifVisuals.rock_material_at` (мох/снег/пыль акта вместо высотных полос).

## L2 — топология акта

`ExpeditionLayout` (v14, наследник `MassifLayout`). Акт — список битов из `route_patterns`: `start` (постоянный зацеп над своей полкой) → `intro` (знакомая механика) → `teach` (новое правило отдельно: ветка или опасность рядом с путём) → `fork` (безопасный обход из 3 рядов против короткой ветки сразу на 3-й ряд, либо выбор кристалла) → `rest` (полка восстановления + постоянный зацеп) → `combo` → `exit` (ориентир и выход к следующему акту). Число рядов фиксировано определением; длинные акты добирают ряды в intro/combo, подъём масштабируется под высоту акта.

Граф проверяется `RouteGraph.audit` (вход израсходован, выходы после скольжения/таймера) плюс `test_levels`: опасности не пересекают основные переносы (с высотами качания 0–4,2 м), не стоят на выходе ветки, разные опасности не делят одно место. Предметы и усиления не размещались.

Новой физики зацепов не потребовалось: «корка» — это таймерная опора пустынного профиля, гладкий лёд — существующее скольжение. Опасности — отдельный слой среды `ActHazards` (дрейф, сбивание с крюка через обычный `release_hook`, однократное обрушение), визуал — `HazardVisuals`, ориентиры — `LandmarkVisuals.build_family`, предметы — `ActProps`.

## L6 — повторные маршруты

У каждого акта 3 варианта развилки (`variants`, то же число рядов): `risky_shortcut`, `collection` (редкая находка на короткой ветке), `speed` (пружина на ветке); у кристальных развилок — `choice`. Вариант выбирается потоком акта; `variant_override` фиксирует его. `LevelCatalog.contract_seed(location, act)` — фиксированный seed контракта; один seed даёт один вариант и маршрут. Награды не реализованы, переданы только теги.

Статистика 50 гор на слот (v14): рядов 43/48/55; доля постоянных 8,8/7,9/10,0 %; типы (камень/корень/пружина/лёд/кристалл): слот 0 — 84/5,6/9,0/0/1,4 %, слот 1 — 86/5,5/8,5/0/0,4 %, слот 2 — 87/0/7,4/5,2/0 %.

## L8 — итоговая проверка

- Три слота запускаются из меню на своей экспедиции (`test_levels`).
- Девять актов с правильным контекстом и профилем на каждой высоте; debug state.
- `RouteGraph.audit`: 0 проблем на 90 горах v14 (тест) и 120 (зонд).
- У каждого акта: старт на полке, основной выход в следующий акт/вершину, альтернативная ветка, полка восстановления.
- Бот базового комплекта проходит всю основную линию всех трёх экспедиций с включёнными опасностями (зонд: 12/12 гор без сбитий; тест — с допуском до 2 восстановлений после промаха бота).
- Ветки пройдены ботом: все типы, кроме внутренней трещины (лёд + сосулька) — 2/3; это заявленный «большой риск», безопасный внешний карниз проверен.
- Буря не меняет направление после старта; мгла не закрывает ничего ближе 7 м (> каната 5,5 м); все бури акта идут по одному такту.
- Перемычка: держит телеграф 1 с, падает один раз, открывает выход, состояние переживает сохранение/загрузку.
- Отпечатки v13 (слот 0) и v4 (слоты 1/2) не изменились.
- Визуальный осмотр (`tools/visual_fixture.gd --acts --location=N`): лес/хребет/руины, пустыня/караван/обсерватория и снег/трещина/корона различаются материалом скалы, погодой, предметами и ориентирами; опасности видны (флаги, ленты, зеркала, кактус с красными шипами, скорпион, сосулька с тенью, перемычка).

## Оставшиеся пробелы чата 3

- Часть битов пропускается, когда нет места (по 40 seed): вводная ветка «Ветрового траверса» ≈30 %, развилка «Сухого каньона» ≈25 %, остальные ≤15 %. Акт при этом сохраняет другие ветки; аудит и тест требуют хотя бы одну альтернативу на акт.
- Ветер и буря ветки сносят только героя, который взял эту ветку (держится или только что ушёл с неё): иначе широкий мах с основного пути заходил в карман и срывал интеграционного бота. На основной путь выходит только циклическая буря «Обсерватории», где ждать можно на камне.
- Один блок зацепа v14 (seed 58273, слот 0, высота блока 1,40 высоты хитбокса) стоит ровно на границе визуального контракта чата 2.1; это свойство `GripVisualSpec`, не уровней.
- В этой же папке параллельно работала сессия чата 4 (`item_catalog.gd`, `loot_placement.gd`, правки тестов); её файлы не трогались, ошибки `ItemCatalog` в логах — от неё.
- Силуэт актов отличается набором форм рельефа и шириной фланга, но на общем плане леса/хребта/руин различие умеренное; сильнее всего акты различают материал, погода, предметы и ориентиры.
- Фон неба (`ProceduralSkyBackdrop`) по актам не меняется.
- Ориентир развилки «Старого поста» (корневая арка) на seed 58273 не находит свободного места на скале и не строится (точка у развилки приходится на открытое небо); ориентиры выхода из актов строятся. Нужен отдельный «держатель» арки или план её точки по массиву.
- Кадры осмотра: `docs/screenshots/chat3/` (обзор каждого акта, опасности в фазе телеграфа, ориентиры).
- Лёд: скольжение идёт по нарисованному контуру блока (`object["surface"]`, чат 2.1) и «никогда вверх». У части ледяных блоков v14 на контуре есть горб, на котором крюк останавливается через ~0,1 м (пример: слот 2, seed 0, опора 11). По упрощённому контуру тот же блок скользит 0,43 м за 0,8 с. Это физика/контур типа зацепа — передаётся владельцу GripSpec/GripVisualSpec, в чате 3 не менялось.
