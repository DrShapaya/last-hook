### Где возможна двойная награда

1. `settle()` — защищён `last_settled == run_id`; `load_profile` очищает уже рассчитанную попытку.
2. `resume_run()` для несовместимого генератора — один `settle()` по id снимка (тот же guard).
3. Зональное золото — `reach()` сразу в `profile.gold` и сразу `save_snapshot()`; в результате показывается отдельно, не начисляется повторно.
4. Миграция — только при `source_version < текущей`; резервная копия мигрирует от собственного кошелька.
5. **Новое:** монета — без журнала id повторный callback или повторный подбор после перезапуска начислил бы её дважды; решено `coin_ledger` + `picked` в одной записи файла (P2).
6. **Новое:** расход заряда активного предмета — списание запаса и отметка «использован» в снимке одной записью (P5).
7. Файл пишется атомарно (`.tmp` → rename, `.bak`) — одна запись профиля является транзакцией.

Старая версия сохранения: **5**. Путь миграции: v1–v4 → (замороженные цены v5) → v5 → v6.

## P1 — миграция профиля (v5 → v6)

Изменено: `game_model.gd`, новый `item_catalog.gd`. Профиль v6 добавляет `upgrade_levels`, `upgrade_choices`, `material_wallet`, `consumable_stock`, `active_loadout`, `coin_ledger`, `unlocked_sets`, `completed_contracts`, а также `set_parts`, `landmarks`, `mastery_tokens`, `reached_acts`.

- Старое `levels` читается только в `_migrate_levels`. v1–v4 сначала приводятся к v5; их компенсация теперь считается по **замороженным** ценам v5 (`V5_UPGRADE_PRICES`, `V5_WEIGHTS`, `V5_TIP_PRICES`), а не по текущему `balance.json`. Затем v5 → v6: стандартные шкалы `min(уровень, 5)`, крюки — та же ступень, и она же выбрана, слоумо — самое длинное новое окно не длиннее купленного (`V5_SLOWMO_SECONDS`). Разница «заплачено − стоит по новым ценам» возвращается один раз; если новые уровни дороже — долга нет.
- Предметы активного рюкзака без `family` читаются как `valuable` по tier (`ItemCatalog.normalize`). Старый `kind:"coin"` один раз переносится в `coin_ledger`: золото начисляется, id остаётся в `picked`, из рюкзака предмет уходит, поэтому settlement его уже не увидит.
- `reached_acts` выводится из `best` по актам первой экспедиции; недостающие поля берут значения нового профиля (в том числе пробный «Маяк опор»).
- Проверено: профили v1, v2, v3 и v5; повторная загрузка (компенсация не повторяется); повреждённый основной файл → `.bak` мигрирует от своего кошелька; активная попытка с монетами. **Копия реального профиля** (v5, `levels` из 7, активная попытка v11 с двумя «монетами» 40 и 72): золото 251 → 363 (+112 через журнал), рюкзак пуст, уровни [2,2,1,2,2,2,2,1], попытка остаётся продолжаемой, повторная загрузка идентична.

## P2 — монеты отдельно от рюкзака

Изменено: `game_model.gd` (`collect_coin`, `begin_run_ledger`, `run_coins`), `main.gd` (`_collect_finds`), `game_hud.gd`.

1. `collect_coin(run_id, item)`: id проверяется в `coin_ledger.ids` текущей попытки → золото сразу в `profile.gold`, запись в журнал, id в `picked`. Затем `main` вызывает `save_snapshot()` — кошелёк, журнал и снимок попытки пишутся **одной** атомарной записью файла.
2. `try_pick` монету не берёт; `bag_value()` считает только `valuable/relic/contract`; `settle()` отдаёт `coins` отдельной строкой и не включает их в `total`.
3. После падения начисленные монеты не откатываются. Повторный callback, повторная генерация и перезапуск игры не начисляют монету второй раз.
4. HUD: плашка кошелька справа под шкалой маршрута и всплывающее «+N» от места монеты; ячейки рюкзака отдельно.
5. Магнит: уровень 2 тянет только монеты, с уровня 3 — и находки (`magnet_coin_radii`, `magnet_radii`).

Проверено (`test_economy`): касание, магнит, полный рюкзак, продолжение после перезапуска, поражение, повторный callback, запись на диск.

## P3 — модель предметов, комплекты, размещение (генератор v15)

Изменено: `item_catalog.gd`, новый `loot_placement.gd`, `expedition_layout.gd`, `mountain_world.gd`, `loot_icon.gd`, `loot_visuals.gd`, `bag_slot.gd`.

- `GENERATION_VERSION = 15`: геометрия, опоры и опасности v14 **без изменений** (тест сравнивает опоры v14 и v15 одного seed); меняется только слой находок. Сохранённые попытки v14 восстанавливаются со старыми находками (`resumable(14)`); отпечатки v13/v4 не изменились.
- Генератор только *запрашивает* точку с ролью; `LootPlacement` разрешает её на два ряда позже, когда известны все опасности, которые могут её задеть, и читает только опасности до `row+2`. Поэтому результат не зависит от того, какими кусками вызывается `generate_to` (тест).
- Роли: `main_safe` (ценность / монета / один региональный материал на акт), `main_coin` (дуга из 3 монет), `detour` (часть комплекта акта + россыпь из 3 монет на подходе, видна до решения), `choice`/`fork_collection` (артефакт ×1,8 за одним понятным риском), `fork_risky_shortcut` (тайник 40–60), `fork_speed` (рисковый материал), `landmark` (один на акт, под опорой выхода; если места нет — под последней опорой акта), `contract_target` (первая находка ветки в акте контракта; если ветки нет — следующий акт).
- Проверки до размещения: внутри массива; не ближе 1,2 м к опорам (если позже строится опора-мостик следующего ряда, находка сдвигается на другую проверенную точку или снимается без смены id); вне препятствий, полок, точек развилок и других находок (≥0,8 м); не в прямоугольнике бури основного пути, не на линии сосульки, не ближе «радиус + 1,5 м» к кактусу и скорпиону. Ветки берутся из уже проверенного графа чата 3 (вход и выход вперёд, базовый комплект), поэтому находка не требует некупленного улучшения. Геометрия актов не менялась.
- Статистика по 20 seed на экспедицию (`docs/validation/chat4-loot-fixture.json`): прямых монет 841 / 865 / 1149 золота на вершину, ценностей 10,7 / 9,4 / 12,7, частей комплекта 5,6 / 5,8 / 6,6, материалов 4,3 / 2,6 / 3,3, ориентиров 3 / 3 / 2,85, контракт 1 / 1 / 1. Проверки отбрасывают ≈2,5–3 `main_safe` и ≈18–21 монету из дуг на гору.

Полный рюкзак: обычная находка остаётся в мире; артефакт или контракт открывает плашку «Взять X (цена) вместо Y (цена)?» с кнопками «Взять» и «Оставить». Без нажатия ничего не заменяется; плашка закрывается, если герой отошёл или находка оказалась за стеной. Отказ запоминается до конца попытки.

## P4 — постоянная прокачка

Изменено: `balance.json`, `game_model.gd`, `main.gd`, `lobby_view.gd`.

- Ворота уровней по прогрессу, а не по зонам 200 м: уровень 2 — сразу; 3 — вход во 2-й акт любой экспедиции; 4 — вход в 3-й акт; 5 — вершина **или** 2 контракта (`upgrade_gates`). Покупка только вне попытки (проверяется моделью).
- Специализации (`specializations`) меняются бесплатно между попытками и запрещены во время попытки: канат «Дальность» (+0,5 м) / «Контроль» (длина меняется в 1,6 раза быстрее) с уровня 3; импульс «Сила» (+6 %) / «Контроль» (отпуск при падении без прибавки) с уровня 3; бросок «Скорость» / «Устойчивость» (скорость ×0,95, крюк наследует 60 % скорости героя) с уровня 3; магнит — приоритет семейства с уровня 5. Крюки — 4 взаимоисключающие схемы, купленные можно переключать.
- Рюкзак: 1–5 слотов, на уровне 5 — шестой слот только для материала, реликвии или контракта. Защита добычи: 30/40/55/70/82 %. Слоумо: 0,70/1,00/1,35/1,75 с.
- Мастерская: в каждой строке написано, где полезен следующий уровень (`upgrade_uses`). Вкладка «Сборы»: профили, слоты, запас, материалы, комплекты/контракты/жетоны.

## P5 — активные предметы

Изменено: `balance.json` (`consumables`), `game_model.gd`, `main.gd`, `game_hud.gd`.

`ConsumableDefinition`: `id, category, duration, charges, price_gold, recipe_materials, max_per_run, conflicts` (+ параметры эффекта). Порядок реализации: маяк, бустер, плавное падение, лента.

| Предмет | Когда можно | Эффект | Цена | Конфликт |
|---|---|---|---:|---|
| Маяк опор | в полёте или на канате, если есть валидный выход | 3 с кольца на 2 выходах (не израсходованы, в длине каната, без перекрытия, основной путь первым) | 140 или 2 волокна | — |
| Импульсный бустер | только в полёте, скорость направлена к видимой опоре (±60°) | 1,4 с ускорение 6 м/с² вдоль текущей скорости, предел 13 | 220 или 2 жилы | — |
| Плавное падение | только в полёте | 3,5 с падение не быстрее 2,2; канат и нижняя граница не меняются | 180 или 2 шёлка | лента |
| Страховочная лента | сама при смертельном срыве, если есть путь назад (`revive_plan`) | возврат на безопасную точку, выпадает последняя не-контрактная находка; продолжение за алмазы/рекламу **не** тратится и не совмещается с этим срывом | 350 или 1 сердце кристалла | плавное падение |

Два слота, в запасе до 2 штук каждого, один заряд каждого за попытку; второй предмет нельзя включить, пока идёт эффект первого. Списание запаса и отметка «использован» сохраняются одной записью снимка; `run_items` и `item_effect` восстанавливаются после перезапуска. Эффект проходит begin (`ITEM_BEGIN`) → active (отсчёт в реальном времени) → end (`ITEM_END`); плавное падение и бустер заканчиваются при зацепе или приземлении, затем физика обычная. Ни один предмет не создаёт опору и не отключает нижнюю зону. На ПК — клавиши 1/2. Алмазы расходники не покупают.

## P6 — цены, стоки, разблокировки

`balance_version: 15`. Источники золота: высота, зоны (как раньше), прямые монеты, продажа рюкзака, контракт; материалы — региональные находки; алмазы — вершины. Стоки: улучшения, расходники, экспедиции, продолжение (алмазы).

- Вторая экспедиция: вершина «Живого хребта» + 2500 золота. Третья: вершина «Солнечного разлома» + 5 жетонов мастерства (порог, не тратятся) + 15 алмазов. Жетоны дают собранный комплект (+1) и первое выполнение контракта (+1). Уже открытые экспедиции сохраняются.
- Проверки: первая покупка после 1-й попытки (120 золота); специализация — после первого акта (ворота уровня 3); бот базового комплекта проходит вершину без расходников (`test_integration`, как и до чата); ранний фарм до 400 м даёт 89–187 золота/мин против 246–497 на полной вершине.

### 6. Ограничения и ручная калибровка

- Таблица P8 — модель чувствительности с заданными долями сбора, а не измерение игры. Нужен пилот: реальная доля собранных монет, частота веток, замены в рюкзаке, использование предметов.
- Полный комплект по стартовой сетке задания стал заметно дешевле (24 891 против ~102 000): 49–123 мин в модели против 90–240 мин раньше. Если пилот подтвердит слишком быстрый рост — поднять `upgrade_prices`, не трогая доходы.
- Лента стоит 10–16 % дохода забега (ориентир плана для сильного спасения — 20–30 %); кандидат на подъём цены после пилота.
- Доля монет у новичка ниже 20 % (14–15 %), у опытного — в цели.
- Монет на гору много (67–93 объекта); плотность нужно оценить на устройстве.
- Ориентир на третьей экспедиции иногда не находит места (≈0,15 на гору).
- Комплект продвигается любой частью своего акта (3 части = комплект). Вариант маршрута или косметика за комплект пока только запись `unlocked_sets` + жетон — **gap для чата 3 / следующей задачи**: вариант маршрута по собранному комплекту через существующие `route_tag`.
- Ракетный подброс и локационные варианты предметов не добавлены (по заданию — отдельным проходом).
- Старый `tools/economy_probe.py` описывает экономику v13 (читает удалённый `tip_prices`) и заменён `tools/economy_table.py`.
- Существующие проблемы вне области чата: `test_grip_types` не находит ледяную ветку и зависает (из-за этого `tools/build.ps1` не дойдёт до экспорта); 7 проверок `test_visuals` и 3 проверки `test_integration` (бот базового комплекта на seed 58273) падали и до чата 4.
