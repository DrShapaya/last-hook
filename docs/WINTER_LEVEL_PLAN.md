# План переделки зимнего уровня

Задача: зимняя локация («Снежная вершина», `sky_city`, location 2, маршруты 0–2) выглядит хуже всех — как плоская стена из треугольников, без объёма и без своего характера. Нужно довести её до референсов по форме, объёму, материалу и деталям. Летнюю гору не трогать. Пустыня уже доведена дальше всех, её подход — образец.

## Референсы

- `references/location/winter_4k.png` — вся гора целиком.
- `references/location/winterClose.png` — крупный план, главный ориентир по объёму и материалу.

Что на них видно:
- Высокая башня из крупных угловатых глыб-колонн, наклонённых в одну сторону (по ветру), с глубокими вертикальными расщелинами между ними.
- Толстые снежные полки выступают из башни: сверху видна белая снежная площадка с камнями, спереди тёмный обрыв, под полкой гроздья голубых сосулек.
- Полки закручиваются вокруг башни спиралью. Есть петли и арки с конусами-зубьями по верху.
- Широкие предгорья с малым пиком сбоку, ступенчатая вершина.
- Парящие скалы-острова с сосульками снизу, крупные голубые кристаллы на кромках, ёлки.
- Камень холодный серо-синий, тени синие, лёд светится голубым.

## Почему сейчас плоско

- Глубина камня почти везде одна и та же, около 2 единиц. У пустыни перепад около 8: края скругляются назад, полки выступают вперёд, под ними ниши, есть пещеры. У зимы этого нет.
- Полки — только раскраска полосой, они не выступают и не показывают верхнюю снежную грань.
- Грани длинные и одинаковые по всей горе: видна равномерная сетка треугольников, а не глыбы и расщелины.
- Тени почти не работают: нет глубоких щелей и выступов, которые их отбрасывали бы.
- Декор ставится по-старому (по невидимым массам), а не по видимому контуру. Сосулек и кристаллов мало.

## Как устроена генерация (что читать)

- `game/scripts/winter_designer.gd` (`WinterDesigner`) — автодизайнер зимы: маска (силуэт), полки, шпили-рога, осколки, предгорья. Пишет полки в бриф (`shelves`).
- `game/scripts/winter_rock.gd` (`WinterRock`) — вид камня: глубина `height()` и цвет граней `facet_color()`, камни на полках `lumps()`.
- `game/scripts/rock_surface.gd` (`RockSurface`) — общая сплошная гранёная поверхность по маске. Подклассы задают глубину и цвет. `holds_objects()` решает, стоят ли объекты на этой поверхности.
- `game/scripts/desert_rock.gd`, `game/scripts/desert_designer.gd` — образец: скругление края назад (`ROLL`, `EDGE_Z`), выпуклые пласты, выступающие полки с нишами, пещеры, песок, трещины.
- `game/scripts/massif_visuals.gd` — сборка участков: `_build_rock_surface`, `_build_ledge_plants` (растения, кристаллы, сосульки), посадка по видимому контуру (`_seats_on_view`, `open_at`, `_top_seat`, `_hang_seat`). Для пустыни посадка по контуру уже включена (через `holds_objects()`), для зимы нет.
- `game/scripts/mask_layout.gd` — уровень из маски: маршрут, развилки, `rock_marks` (полки из брифа).
- `game/scripts/level_designer.gd` — базовый автодизайнер и `LevelDesigner.make()`.
- `docs/LEVEL_PIPELINE.md` — описание всей системы уровней, раздел «Свой генератор у каждой локации» и «Доработки по локациям».

## Этапы

### 1. Объём (главное)
- Край башни скругляется назад, сама башня стоит далеко вперёд от фона. Перепад глубины не меньше, чем у пустыни.
- Башня из крупных угловатых глыб-колонн с наклоном по ветру, глубокие вертикальные расщелины между ними.
- Грани крупнее и ровнее, чем сейчас: читаются плоскости глыб, а не сетка треугольников.
- Тест в `game/tests/test_masks.gd`: перепад глубины зимнего камня (как уже есть для пустыни).

### 2. Полки и снег
- Полки — толстые плиты, выступающие из башни. Верх наклонён к зрителю, видна снежная площадка, спереди тёмный обрыв.
- Снежные шапки на всех верхних гранях, синеватая тень в складках, наметённый снег у стен.
- Голубой подсвеченный лёд в расщелинах, потёки под полками.

### 3. Силуэт и маска
- Полки спиралью вокруг башни.
- Петли и арки с конусами-зубьями по верху.
- Широкие предгорья с малым пиком, ступенчатая вершина-корона.
- Парящие скалы-острова с сосульками снизу.
- Острые зубья только там, где они есть на картине; остальной контур без колючек (владелец отвергает острые углы на контуре).

### 4. Детали
- Посадка декора по видимому контуру, как в пустыне (`holds_objects()` у `WinterRock` и проверка аудитом).
- Гроздья сосулек под каждой полкой и островом.
- Кристаллы на кромках, камни на снежных полках, ёлки и заснеженные кусты.

### 5. Погода
- Падающий снег поверх экрана (на пресете battery реже или без него).
- Снег, сдуваемый с кромок.
- Заметные снежные порывы (`blizzard_gust`) над обходами развилок.

### 6. Своя игра у зимы
- Больше ледяных зацепов, падающие сосульки как опасность, снежные полки как передышки.
- Маршрут поднимается вокруг башни по спирали, а не прямо вверх.

### 7. Проверка после каждого этапа
- Сравнение с `winter_4k.png` целиком и с `winterClose.png` вблизи, в кадре из игры, а не только на рендере уровня (в игре свет ярче).
- Аудит декора: ноль ошибок ещё не значит хорошо, количество декора не должно резко упасть.
- Бот на всех трёх уровнях зимы (основной путь и через развилки).
- Полный набор тестов.
- Нагрузка: граней и частиц станет больше.

Начинать с этапа 1. После этапов 1 и 2 показать владельцу сравнение с картиной до работы над маской.

## Инструменты (из корня репозитория)

Godot: `tools/godot/Godot_v4.7.2-stable_win64_console.exe`. Перед запуском задавать `LASTHOOK_SAVE_DIR` на временную папку. Новые `class_name` требуют `--headless --path game --import`.

- Проектирование уровней с ботом: `--headless --path game --script res://tools/design_levels.gd -- --only=2:0 --tries=10 --variant=N` (без бота: `--no-bot`). Варианты отбираются по оценке, бот проходит лучший.
- Запекание: `--headless --path game --script res://tools/bake_levels.gd -- --only=2:0`.
- Рендер уровня целиком: `--path game --script res://tools/level_shot.gd -- res://levels/sky_city_r0 <out.png>`.
- Окна уровня вблизи: `--path game --script res://tools/level_closeups.gd -- res://levels/sky_city_r0 <prefix> 24 26`.
- Аудит декора: `--headless --path game --script res://tools/decor_audit.gd -- 2:0 2:1 2:2`.
- Бот на запечённом уровне: `--headless --path game --script res://tools/climb_level.gd -- 2:0`.
- Тесты: каждый `game/tests/test_*.gd` через `--headless --path game --script res://tests/<имя>.gd`; список в `tools/build.ps1`.
- Кадр из игры: `--capture` показывает мир по сиду, а не запечённый уровень. Для настоящего кадра запускать забег через `model.set_route_choice(location,route)` и `start_run(false)`.

## Правила работы

- Летнюю гору не менять. Пустыню не ломать (её тесты и аудит должны оставаться зелёными).
- Уровни поставляются запечёнными (`game/levels`): после изменений генератора или вида перезапекать, после изменений маски перепроектировать с ботом.
- Сравнивать силуэт всего уровня, а не только фактуру вблизи, и смотреть контур в игровом масштабе.
- Параллельно в репозитории работают другие сессии (небо, шейдер камня `massif_rock.gdshader`, настройки, движение). Их незакоммиченные файлы не трогать и в свои коммиты не включать. Проверять текущую ветку перед коммитом.
- Коммитить и пушить только по просьбе владельца. В коммитах только свои файлы и перезапечённые уровни.
- Известные падения, не связанные с уровнями: `test_integration` (сид 410021) и `test_levels` (28 из 31 веток) падают и на чистом коде после изменений движения.
