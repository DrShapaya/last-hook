# План: полировка интерфейса, анимаций и устранение рывков

> **Для исполнителя:** план выполняется в этой же сессии по задачам ниже (superpowers:executing-plans). Шаги отмечаются флажками.

**Цель:** интерфейс без обрезаний и наложений на телефонных экранах, единые по длительности и плавности анимации, ни одного кадра дольше ~25 мс в обычных переходах (на ПК), известные ошибки исправлены и закрыты тестами.

**Подход:** сначала измерение (инструмент `game/tools/flow_profile.gd` проходит реальные экраны, пишет время каждого кадра и снимает кадры), потом точечные правки. Визуальный стиль (каменные плиты, шрифты) не меняется. Крупных переделок нет; идеи переделок вынесены в конец как предложения.

**Технологии:** Godot 4.7, gl_compatibility, GDScript; тесты `game/tests/*.gd` (headless).

**Задание:** сообщение основной сессии от 2026-11-12 (части A и B).

## Общие ограничения

- Не коммитить, не выпускать, не пушить без просьбы владельца.
- Не трогать чужие незакоммиченные файлы; уровни не перепекать (генератор и вид гор не меняются).
- `reduce_effects` выключает декоративное движение (пружины, вспышки, счётчики), но не обратную связь нажатия.
- Длительности UI: нажатие 0,07–0,12 с, переходы и плашки 0,18–0,26 с, счётчики до 0,6 с.
- Каждый набор тестов запускается со своей пустой папкой `LASTHOOK_SAVE_DIR`.

## Что показали измерения (ПК, RTX 4060, окно 540×1170, до правок)

| Место | Кадр, мс | Причина |
|---|---|---|
| Лобби через ~1 с после открытия; после смены локации; после экрана результата | 130–340 | первый показ подготовленной горы (≈800 мешей) в одном кадре за кадром меню |
| Смена пресета графики | 150–210 (первый раз в установке — секунды) | пересоздание теневого атласа и варианты шейдеров |
| «Начать заново» с экрана падения раньше, чем гора подготовлена | 150–220 | гора строится синхронно |
| Создание подготовленной горы (кадр 2 после смены локации) | 40–70 | синхронное чтение запечённого уровня |
| Сборка секций горы в фоне | 35–48 | одна секция за кадр — слишком большой кусок |
| Заготовка соседних страниц меню (через 0,35 с простоя) | 45–57 | страница «Восхождение» строится за один кадр |
| Старт забега | 40–90 | шейдеры героя, тени, контактов создавались заново на каждый забег |
| Открытие экрана персонажа | 26–57 | шейдеры уступа/героя заново, сборка экрана |
| Результат → через ~13 кадров | 65–88 | тот же первый показ подготовленной горы |

На телефоне каждое из этих чисел в 3–6 раз больше.

## На что смотреть при проверке

1. Забег, начатый в момент, когда гора ещё «прогревается» по частям: все части должны быть видны с первого кадра.
2. Экран персонажа открыт в момент прихода баннера (меняется высота меню): экран не должен остаться под баннером.
3. Быстрые двойные нажатия на «Начать», «В лагерь», «Купить», вкладки: одно действие, без двойной анимации.
4. `reduce_effects` включён: никаких пружин и счётчиков, итоговые значения стоят сразу.
5. Масштаб текста 130 % на экране 16:9 (самый тесный случай): нет обрезаний.

## Задача 5. Пустая сцена на экране персонажа

Воспроизвести на ПК не удалось (25 сценариев: пауза/возврат приложения, сворачивание, приход баннера, быстрые закрытие/открытие, пресеты, после забегов). Найдены три настоящих дефекта, каждый из которых на телефоне может дать пустую сцену:

1. Цель рендера сцены ~1000×1400 px с MSAA 4× — 45–80 МБ видеопамяти; при быстром повторном открытии живут две сразу. При нехватке памяти цель не создаётся — рисуется только картина-фон.
2. Экран не следует за меню, когда меняется высота баннера: остаётся на старом месте.
3. Закрывающийся экран продолжает рисовать сцену до конца кадра удаления.

**Файлы:** `game/scripts/character_screen.gd`, `game/scripts/lobby_view.gd`, тест `game/tests/test_character_screen.gd`.

- [ ] Цель рендера не больше `MAX_STAGE_PIXELS := 1_100_000`; на телефоне MSAA 2×.
- [ ] `release_stage()` — закрывающийся экран отдаёт цель рендера сразу при повторном открытии.
- [ ] Самопроверка: через 0,5 с после открытия и после возврата в приложение экран читает свою сцену; если она пустая — пересобирает её без MSAA и шлёт событие `character_stage_empty` в AppMetrica (узнаем, случается ли это у игроков).
- [ ] `LobbyView.update_layout()` передвигает открытый экран персонажа.
- [ ] Тесты: размер цели под ограничением; повторное открытие во время закрытия освобождает старую сцену; экран следует за меню.

- [ ] Константы: `PRESS := .08`, `RELEASE := .16`, `FADE := .18`, `SLIDE := .24`, `COUNT := .6`; все твины экранов берут их.
- [ ] Нажатие: отпускание 0,3 с → 0,16 с; при `reduce_effects` без пружины.
- [ ] Диалог выхода, пауза, «ещё один шанс»: появление плашки (сдвиг 16 px + проявление за 0,2 с), ввод не теряется.

- [ ] Покупка улучшения/цвета: кошелёк досчитывает до нового значения.
- [ ] Тест `test_polish.gd`: длительности из констант; при `reduce_effects` значения стоят сразу.
